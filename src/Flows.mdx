# Flows & Tours

Create guided tours and onboarding experiences with the `useTour` hook — a simplified, declarative API for multi-step tours.

## Overview

The `useTour` hook provides everything you need for guided tours:

- **Declarative step definitions** — Define steps with targets, content, and options
- **Automatic tooltip management** — No manual tooltip.show() calls needed
- **Built-in navigation** — Optional in-tooltip navigation controls
- **Progress indicators** — Steps text or circular ring progress
- **Focus mode** — Backdrop overlay to highlight elements
- **Rich media support** — Images, GIFs, and videos in tooltips
- **Callbacks & events** — Track tour progress and user actions

## Quick Start

```tsx
import { useTour } from 'react-tip-magic';

function OnboardingTour() {
  const tour = useTour({
    steps: [
      { target: 'sidebar', content: 'Navigate between sections.' },
      { target: 'search', content: 'Find anything quickly.' },
      { target: 'profile', content: 'Access your settings.' },
    ],
    tooltipOptions: {
      placement: 'bottom',
      maxWidth: 300,
    },
  });

  return (
    <div>
      {!tour.isActive ? (
        <button onClick={tour.start}>Start Tour</button>
      ) : (
        <>
          <span>
            Step {tour.progress.current} of {tour.progress.total}
          </span>
          <button onClick={tour.prev} disabled={tour.currentStep?.isFirst}>
            Back
          </button>
          <button onClick={tour.next}>{tour.currentStep?.isLast ? 'Finish' : 'Next'}</button>
          <button onClick={tour.end}>Exit</button>
        </>
      )}
    </div>
  );
}
```

### Target Elements

Add `data-tip-id` attributes to elements you want to reference in your tour:

```tsx
<nav data-tip-id="sidebar">{/* Sidebar content */}</nav>
<input data-tip-id="search" placeholder="Search..." />
<div data-tip-id="profile">{/* Profile menu */}</div>
```

## useTour Options

The `useTour` hook accepts a configuration object:

```tsx
const tour = useTour({
  steps: [...],           // Required: Array of TourStep
  tooltipOptions: {...},  // Optional: Default tooltip options for all steps
  navigation: {...},      // Optional: Navigation configuration
  progress: {...},        // Optional: Progress indicator options
  focus: false,           // Optional: Backdrop - boolean, or { block, dismissOnClick }
  mediaPlacement: 'top',  // Optional: Where media sits - 'top' | 'left' | 'right'
  onStart: () => {},      // Optional: Called when tour starts
  onEnd: (completed) => {},  // Optional: Called when tour ends
  onStepChange: (step, direction) => {},  // Optional: Called on navigation
  onTargetMissing: (step) => {},  // Optional: A step's target is not in the DOM
});
```

### Focus mode

`focus: true` dims the app behind a purely visual backdrop - it does not capture pointer
events, so the app stays interactive and the user can navigate away from the highlighted
element. Pass an object to change that:

```tsx
focus: {
  block: true;
} // Stop clicks from reaching the app behind the backdrop
focus: {
  dismissOnClick: true;
} // Clicking the backdrop ends the tour (implies block)
```

### When a target is missing

`start()` returns `false` and changes nothing - no `onStart`, no `onStepChange` - if no
step's target is in the DOM, so a tour that cannot render never reports itself as shown:

```tsx
if (tour.start()) {
  markTourAsSeen();
}
```

`onTargetMissing` fires instead of the library's `console.warn`, which lets a host route
it through its own logger. Return `'skip'` to continue with the next resolvable step;
anything else ends the tour, or prevents it from starting when the first step fails.

```tsx
onTargetMissing: (step) => {
  logger.warn('tour target missing', { target: step.target });
  return 'skip';
};
```

Recovery depends on the direction of travel. `next()` skips or ends. `prev()` and
`goTo()` leave the tour where it is instead, since the step on screen is still fine, and
`goTo()` never skips - it lands on the step you asked for or returns `false`.

A target that is unmounted while the tour is running is treated the same way.

### A step without a target opens centered

A step that is not about any element - an announcement, a welcome, a closing note - leaves
out `target`. It opens centered in the viewport and stays there as the page scrolls or
resizes, with no arrow, and with the focus backdrop on (nothing is cut out of it). Set
`focus: false` on the step or the tour to turn the backdrop off, or
`focus: { dismissOnClick: true }` to let a click on it end the tour.

```tsx
const announcement = useTour({
  steps: [
    {
      id: 'whats-new',
      title: "What's new",
      image: '/release.png',
      body: <Markdown source={releaseNotes} />,
    },
  ],
  navigation: { showControls: true, finishLabel: 'Got it' },
  tooltipOptions: { maxWidth: 420 },
});
```

A centered panel is at most 80% of the viewport's height
(`--tip-magic-tour-centered-max-height`); its body scrolls past that.

**Its image sets its width.** A centered step with an `image` or a native `video` takes
the media's natural width, capped at 70% of the viewport (`--tip-magic-tour-centered-max-width`,
and an explicit `tooltipOptions.maxWidth` if you set one); the title, body and footer wrap
inside it. The media is never cropped or distorted: when it would leave too little height
for the title, a few lines of body and the footer
(`--tip-magic-tour-media-reserved-height`), it is scaled down uniformly. The panel is never
narrower than 280px (`--tip-magic-tour-min-width`) - a smaller image is centered at its
natural size, not stretched. The panel stays hidden until the media's size is known, so it
does not open narrow and then widen. Without media, or with an embedded video, which has no
size of its own, the width comes from `maxWidth` as for any tooltip.

A step can also be only its media: `{ video: { src, title } }`, with no title or text.
Its panel is named by `video.title` (default `'Tour video'`), and with nothing else in
the panel the media may take nearly all of the 80% height. With
`navigation: { showControls: false, showClose: false }` and
`focus: { dismissOnClick: true }` it has no buttons at all: a click outside it or Escape
closes it.

Everything else works as for an anchored step: the same panel, media, `text` / `body` /
`content`, navigation, progress, `autoFocus` and Escape. With no target there is nothing to
highlight, scroll to or watch, so `onTargetMissing` never fires for it. Centered and
anchored steps mix freely - a centered intro, anchored steps, a centered outro - and the
arrow comes back for the anchored ones. Give a centered step an `id` if `steps` can change
while it is on screen: with no target, it can only be told apart by its position.

See the **[Announcement](?path=/story/tooltip-flow-tours--announcement)** story.

### React content

`body` takes any React node, so a step can render your own components - markdown, a
link, a button with its own `onClick`:

```tsx
const tour = useTour({
  steps: [
    {
      target: 'whats-new',
      title: "What's new",
      body: <Markdown source={releaseNotes} />,
    },
  ],
});
```

The panel is React too, so its title, button labels and `text` are escaped by React; only
`content` is injected as HTML.

`body` renders inside `TipMagicProvider`, not inside the component that called `useTour`,
so it sees only the context providers that wrap `TipMagicProvider`. Put providers the body
needs (a theme, a router) above it.

A running step follows changes to `steps`: re-render with a new `body` - release notes
that arrived after `start()`, say - and the panel on screen updates in place, without
moving focus or firing `onStepChange` again. A changed `placement` or other tooltip
option is applied too, and the helper flow (`useTipMagic().helper`) follows the new list.

When steps are added, removed or filtered out, the step on screen is found again by its
`id`, or by its `target` when no other step shares it. If a `condition` filters out an
earlier step, it stays on screen at its new position. If it is removed - or it has no `id`
and shares its `target` with another step, so it cannot be told apart - the tour moves on
to the step now at its place, with `onExit`, `onEnter` and `onStepChange` firing as for
`next()`; if there is none, the tour ends. **Give steps an `id`, or unique targets, if
`steps` can change while the tour runs.**

A long body scrolls: `.tip-magic-tour-body` stops growing at
`--tip-magic-tour-body-max-height` (`60vh` by default), and the panel shrinks the body
further when there is less room beside the target.

### Dynamic Content

`body` and `content` can be functions that receive step info:

```tsx
{
  target: 'sidebar',
  body: (step) => <p>Step {step.index + 1} of {step.total}: Welcome!</p>
}
```

## Navigation Options

Configure built-in navigation controls:

```tsx
navigation: {
  showControls: true,      // Show Next/Back buttons in tooltip
  showClose: true,         // Show close (×) button
  closeLabel: 'Close',     // Accessible name of the close button
  nextLabel: 'Next',       // Custom label for Next button
  backLabel: 'Back',       // Custom label for Back button
  finishLabel: 'Finish',   // Label for last step's button
  autoFocus: 'panel',      // Where focus lands: 'panel' | 'primary' | false
}
```

When `showControls` is enabled, navigation buttons are rendered inside the tooltip automatically.

### Where focus lands

A tour panel is a `role="dialog"`, so focus moves into it when a step opens — otherwise a
screen reader is never told it appeared, and Escape would not be reachable.
`autoFocus` controls which element inside it receives that focus.

<table>
  <thead>
    <tr>
      <th>Value</th>
      <th>Focus lands on</th>
      <th>Pressing Enter</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>
        <code>'panel'</code> (default)
      </td>
      <td>The tour panel itself</td>
      <td>Nothing, until the user Tabs to a control</td>
    </tr>
    <tr>
      <td>
        <code>'primary'</code>
      </td>
      <td>Next, or Finish on the last step</td>
      <td>Advances the tour</td>
    </tr>
    <tr>
      <td>
        <code>false</code>
      </td>
      <td>Nothing — focus is left where it was</td>
      <td>Whatever the page already did</td>
    </tr>
  </tbody>
</table>

```tsx
// A read-and-advance tour: Enter goes to the next step
const tour = useTour({
  steps,
  navigation: { showControls: true, autoFocus: 'primary' },
});
```

`'primary'` falls back to the panel when a step renders no primary action — with
`showControls` off, for example. It never falls back to the close button, since Enter on
that would end the tour.

`false` is an escape hatch for consumers moving focus themselves. It gives up the dialog
announcement and leaves focus behind the panel, so prefer `'panel'` unless you have a
reason.

Like the rest of `navigation`, it can be overridden per step:

```tsx
steps: [
  { target: 'intro', content: 'Read this first', navigation: { autoFocus: 'panel' } },
  { target: 'action', content: 'Now press Enter', navigation: { autoFocus: 'primary' } },
];
```

Steps that render as a plain tooltip rather than a dialog — a `text` or `content` step
with no title, navigation controls, close button, media or progress — never move focus,
whatever `autoFocus` is set to. A `body` step always renders the panel.

## Progress Options

Show step progress in the tooltip:

```tsx
// Text progress: "Step 1 of 5"
progress: { show: true, type: 'steps' }

// Ring progress: Circular progress indicator
progress: { show: true, type: 'ring' }

// Custom render
progress: {
  show: true,
  render: ({ currentStep, totalSteps }) =>
    `<span>📍 ${currentStep} / ${totalSteps}</span>`
}
```

## Focus Mode

Add a backdrop overlay to highlight the current target:

```tsx
// Enable for entire tour
const tour = useTour({
  steps: [...],
  focus: true,
});

// Or enable per step
const tour = useTour({
  steps: [
    { target: 'intro', content: 'No focus here' },
    { target: 'important', content: 'This step has focus!', focus: true },
    { target: 'outro', content: 'No focus here either' },
  ],
});
```

Customize the backdrop via CSS:

```css
.tip-magic-tour-backdrop {
  --tip-magic-tour-backdrop-blur: 4px;
  --tip-magic-tour-backdrop-bg: rgba(0, 0, 0, 0.3);
}
```

### Always Visible Elements

Some UI elements like headers, navigation sidebars, or toolbars should remain accessible during a tour — even when focus mode is active. Use `data-tip-always-visible` to exclude elements from being masked:

```tsx
{
  /* Header stays visible during tour focus */
}
<header data-tip-always-visible>
  <nav>Navigation</nav>
  <div className="user-menu">User Menu</div>
</header>;

{
  /* Sidebar stays visible */
}
<aside data-tip-always-visible>
  <ul>
    <li>Home</li>
    <li>Settings</li>
  </ul>
</aside>;

{
  /* Main content will be masked as normal during focus */
}
<main>
  <div data-tip-id="step1">Tour target</div>
</main>;
```

Elements with `data-tip-always-visible`:

- Appear above the backdrop alongside the focused tour target
- Remain fully interactive during the tour
- Apply to the element and all its children

This is useful for:

- **Application headers** — Users can still access navigation or exit the app
- **Sidebars** — Keep navigation accessible throughout the tour
- **Toolbars** — Allow users to access tools while learning

## Media Support

Add images, GIFs, or videos to tour steps:

```tsx
// Static image or GIF
{
  target: 'feature',
  title: 'New Feature',
  content: 'Check out this amazing feature!',
  image: 'https://example.com/demo.gif'
}

// Embedded video (YouTube, Vimeo)
{
  target: 'video-demo',
  content: 'Watch how it works:',
  video: {
    src: 'https://www.youtube.com/embed/VIDEO_ID',
    type: 'embed',
    title: 'Setting up alerts' // The iframe's accessible name (default: 'Tour video')
  }
}

// Native video (mp4)
{
  target: 'tutorial',
  content: 'Follow along:',
  video: {
    src: 'https://example.com/tutorial.mp4',
    type: 'native',
    autoplay: true,
    loop: true,
    muted: true
  }
}
```

### Media Placement

`mediaPlacement` puts a step's image or video above its text (`'top'`, the default) or in a
column of its own to the `'left'` or `'right'` of it. Set it for the whole tour, and
override it per step:

```tsx
const tour = useTour({
  steps: [
    { title: "What's new", image: '/release.png', body: <ReleaseNotes /> },
    { target: 'search', title: 'Search', image: '/search.gif', text: 'Find anything' },
  ],
  mediaPlacement: 'left',
});
```

Beside the text, the panel is two columns: the media, and a text column with the title,
the body - which takes the height left and scrolls - and the buttons at the bottom. The
close button stays at the panel's top-right corner. The text column takes up to half of
the panel, between 280px (`--tip-magic-tour-min-width`) and 400px
(`--tip-magic-tour-side-text-max-width`); the media gets the rest, keeping its aspect ratio
and never taller than the panel may be. A centered panel stays within 70% of the viewport's
width and 80% of its height; an anchored one within the viewport, the room beside its target
and an explicit `maxWidth`.

Below a 640px viewport the media goes back on top, and a step with no media, or with
nothing but media, ignores the option.

## Callbacks

Track tour events for analytics or custom behavior:

```tsx
const tour = useTour({
  steps: [...],
  onStart: () => {
    console.log('Tour started');
    analytics.track('tour_started');
  },
  onEnd: (completed) => {
    console.log(completed ? 'Tour completed' : 'Tour skipped');
    analytics.track('tour_ended', { completed });
  },
  onStepChange: (step, direction) => {
    console.log(`Moved ${direction} to step ${step.index + 1}`);
  },
});

// Per-step callbacks
const tour = useTour({
  steps: [
    {
      target: 'important',
      content: 'Key feature',
      onEnter: () => console.log('Entered important step'),
      onExit: () => console.log('Left important step'),
    },
  ],
});
```

If the component that called `useTour` unmounts while the tour is running, the panel,
backdrop and highlight are taken down without calling `onExit` or `onEnd`.

## Conditional Steps

Skip steps based on runtime conditions:

```tsx
const [isPremiumUser] = useState(false);

const tour = useTour({
  steps: [
    { target: 'basic', content: 'Available to all users' },
    {
      target: 'premium',
      content: 'Premium feature!',
      condition: () => isPremiumUser, // Only shown if true
    },
    { target: 'footer', content: 'Thanks for touring!' },
  ],
});
```

## Best Practices

### Keep Steps Concise

Each step should focus on one concept:

```tsx
// ✅ Good: Focused message
{
  content: 'Click here to create a new project.';
}

// ❌ Bad: Too much information
{
  content: 'Click here to create a project. You can also import, duplicate, or use templates...';
}
```

### Use Logical Flow

Order steps in the sequence users naturally discover features.

### Provide Exit Options

Always let users skip or exit the tour — use `showClose: true` in navigation.

### Use Focus for Important Steps

Enable focus mode on key steps to draw attention without overwhelming users.

## Accessibility

- Tooltips are keyboard accessible
- Respects `prefers-reduced-motion` for animations
- The close button is named by `navigation.closeLabel` (default `'Close'`), and an embedded
  video by `video.title` (default `'Tour video'`)
- The tour panel is a `role="dialog"` labelled by the step title - or, for a step without
  one, by its message - and focus moves into it when a step opens so it is announced. Pick
  which element receives that focus with [`navigation.autoFocus`](#where-focus-lands)
- The panel is deliberately non-modal: the app behind it stays interactive and there is no
  focus trap, so `Escape` always exits
- Focus returns to whatever held it before the tour when the tour ends
