# Flows & Tours

Create guided tours and onboarding experiences with the `useTour` hook — a simplified, declarative API for multi-step tours.

## Overview

The `useTour` hook provides everything you need for guided tours:

- **Declarative step definitions** — Define steps with targets, content, and options
- **Automatic tooltip management** — No manual tooltip.show() calls needed
- **Built-in navigation** — Optional in-tooltip navigation controls
- **Progress indicators** — Steps text or circular ring progress
- **Focus mode** — Backdrop overlay to highlight elements
- **Rich media support** — Images, GIFs, and videos in tooltips
- **Callbacks & events** — Track tour progress and user actions

## Quick Start

```tsx
import { useTour } from 'react-tip-magic';

function OnboardingTour() {
  const tour = useTour({
    steps: [
      { target: 'sidebar', content: 'Navigate between sections.' },
      { target: 'search', content: 'Find anything quickly.' },
      { target: 'profile', content: 'Access your settings.' },
    ],
    tooltipOptions: {
      placement: 'bottom',
      maxWidth: 300,
    },
  });

  return (
    <div>
      {!tour.isActive ? (
        <button onClick={tour.start}>Start Tour</button>
      ) : (
        <>
          <span>
            Step {tour.progress.current} of {tour.progress.total}
          </span>
          <button onClick={tour.prev} disabled={tour.currentStep?.isFirst}>
            Back
          </button>
          <button onClick={tour.next}>{tour.currentStep?.isLast ? 'Finish' : 'Next'}</button>
          <button onClick={tour.end}>Exit</button>
        </>
      )}
    </div>
  );
}
```

### Target Elements

Add `data-tip-id` attributes to elements you want to reference in your tour:

```tsx
<nav data-tip-id="sidebar">{/* Sidebar content */}</nav>
<input data-tip-id="search" placeholder="Search..." />
<div data-tip-id="profile">{/* Profile menu */}</div>
```

## useTour Options

The `useTour` hook accepts a configuration object:

```tsx
const tour = useTour({
  steps: [...],           // Required: Array of TourStep
  tooltipOptions: {...},  // Optional: Default tooltip options for all steps
  navigation: {...},      // Optional: Navigation configuration
  progress: {...},        // Optional: Progress indicator options
  focus: false,           // Optional: Backdrop - boolean, or { block, dismissOnClick }
  onStart: () => {},      // Optional: Called when tour starts
  onEnd: (completed) => {},  // Optional: Called when tour ends
  onStepChange: (step, direction) => {},  // Optional: Called on navigation
  onTargetMissing: (step) => {},  // Optional: A step's target is not in the DOM
});
```

### Focus mode

`focus: true` dims the app behind a purely visual backdrop - it does not capture pointer
events, so the app stays interactive and the user can navigate away from the highlighted
element. Pass an object to change that:

```tsx
focus: {
  block: true;
} // Stop clicks from reaching the app behind the backdrop
focus: {
  dismissOnClick: true;
} // Clicking the backdrop ends the tour (implies block)
```

### When a target is missing

`start()` returns `false` and changes nothing - no `onStart`, no `onStepChange` - if no
step's target is in the DOM, so a tour that cannot render never reports itself as shown:

```tsx
if (tour.start()) {
  markTourAsSeen();
}
```

`onTargetMissing` fires instead of the library's `console.warn`, which lets a host route
it through its own logger. Return `'skip'` to continue with the next resolvable step;
anything else ends the tour, or prevents it from starting when the first step fails.

```tsx
onTargetMissing: (step) => {
  logger.warn('tour target missing', { target: step.target });
  return 'skip';
};
```

Recovery depends on the direction of travel. `next()` skips or ends. `prev()` and
`goTo()` leave the tour where it is instead, since the step on screen is still fine, and
`goTo()` never skips - it lands on the step you asked for or returns `false`.

A target that is unmounted while the tour is running is treated the same way.

### Dynamic Content

Step content can be a function that receives step info:

```tsx
{
  target: 'sidebar',
  content: (step) => `Step ${step.index + 1} of ${step.total}: Welcome!`
}
```

## Navigation Options

Configure built-in navigation controls:

```tsx
navigation: {
  showControls: true,      // Show Next/Back buttons in tooltip
  showClose: true,         // Show close (×) button
  nextLabel: 'Next',       // Custom label for Next button
  backLabel: 'Back',       // Custom label for Back button
  finishLabel: 'Finish',   // Label for last step's button
  autoFocus: 'panel',      // Where focus lands: 'panel' | 'primary' | false
}
```

When `showControls` is enabled, navigation buttons are rendered inside the tooltip automatically.

### Where focus lands

A tour panel is a `role="dialog"`, so focus moves into it when a step opens — otherwise a
screen reader is never told it appeared, and Escape would not be reachable.
`autoFocus` controls which element inside it receives that focus.

<table>
  <thead>
    <tr>
      <th>Value</th>
      <th>Focus lands on</th>
      <th>Pressing Enter</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>
        <code>'panel'</code> (default)
      </td>
      <td>The tour panel itself</td>
      <td>Nothing, until the user Tabs to a control</td>
    </tr>
    <tr>
      <td>
        <code>'primary'</code>
      </td>
      <td>Next, or Finish on the last step</td>
      <td>Advances the tour</td>
    </tr>
    <tr>
      <td>
        <code>false</code>
      </td>
      <td>Nothing — focus is left where it was</td>
      <td>Whatever the page already did</td>
    </tr>
  </tbody>
</table>

```tsx
// A read-and-advance tour: Enter goes to the next step
const tour = useTour({
  steps,
  navigation: { showControls: true, autoFocus: 'primary' },
});
```

`'primary'` falls back to the panel when a step renders no primary action — with
`showControls` off, for example. It never falls back to the close button, since Enter on
that would end the tour.

`false` is an escape hatch for consumers moving focus themselves. It gives up the dialog
announcement and leaves focus behind the panel, so prefer `'panel'` unless you have a
reason.

Like the rest of `navigation`, it can be overridden per step:

```tsx
steps: [
  { target: 'intro', content: 'Read this first', navigation: { autoFocus: 'panel' } },
  { target: 'action', content: 'Now press Enter', navigation: { autoFocus: 'primary' } },
];
```

Steps that render as a plain tooltip rather than a dialog — no navigation controls, close
button, media or progress — never move focus, whatever `autoFocus` is set to.

## Progress Options

Show step progress in the tooltip:

```tsx
// Text progress: "Step 1 of 5"
progress: { show: true, type: 'steps' }

// Ring progress: Circular progress indicator
progress: { show: true, type: 'ring' }

// Custom render
progress: {
  show: true,
  render: ({ currentStep, totalSteps }) =>
    `<span>📍 ${currentStep} / ${totalSteps}</span>`
}
```

## Focus Mode

Add a backdrop overlay to highlight the current target:

```tsx
// Enable for entire tour
const tour = useTour({
  steps: [...],
  focus: true,
});

// Or enable per step
const tour = useTour({
  steps: [
    { target: 'intro', content: 'No focus here' },
    { target: 'important', content: 'This step has focus!', focus: true },
    { target: 'outro', content: 'No focus here either' },
  ],
});
```

Customize the backdrop via CSS:

```css
.tip-magic-tour-backdrop {
  --tip-magic-tour-backdrop-blur: 4px;
  --tip-magic-tour-backdrop-bg: rgba(0, 0, 0, 0.3);
}
```

### Always Visible Elements

Some UI elements like headers, navigation sidebars, or toolbars should remain accessible during a tour — even when focus mode is active. Use `data-tip-always-visible` to exclude elements from being masked:

```tsx
{
  /* Header stays visible during tour focus */
}
<header data-tip-always-visible>
  <nav>Navigation</nav>
  <div className="user-menu">User Menu</div>
</header>;

{
  /* Sidebar stays visible */
}
<aside data-tip-always-visible>
  <ul>
    <li>Home</li>
    <li>Settings</li>
  </ul>
</aside>;

{
  /* Main content will be masked as normal during focus */
}
<main>
  <div data-tip-id="step1">Tour target</div>
</main>;
```

Elements with `data-tip-always-visible`:

- Appear above the backdrop alongside the focused tour target
- Remain fully interactive during the tour
- Apply to the element and all its children

This is useful for:

- **Application headers** — Users can still access navigation or exit the app
- **Sidebars** — Keep navigation accessible throughout the tour
- **Toolbars** — Allow users to access tools while learning

## Media Support

Add images, GIFs, or videos to tour steps:

```tsx
// Static image or GIF
{
  target: 'feature',
  title: 'New Feature',
  content: 'Check out this amazing feature!',
  image: 'https://example.com/demo.gif'
}

// Embedded video (YouTube, Vimeo)
{
  target: 'video-demo',
  content: 'Watch how it works:',
  video: {
    src: 'https://www.youtube.com/embed/VIDEO_ID',
    type: 'embed'
  }
}

// Native video (mp4)
{
  target: 'tutorial',
  content: 'Follow along:',
  video: {
    src: 'https://example.com/tutorial.mp4',
    type: 'native',
    autoplay: true,
    loop: true,
    muted: true
  }
}
```

## Callbacks

Track tour events for analytics or custom behavior:

```tsx
const tour = useTour({
  steps: [...],
  onStart: () => {
    console.log('Tour started');
    analytics.track('tour_started');
  },
  onEnd: (completed) => {
    console.log(completed ? 'Tour completed' : 'Tour skipped');
    analytics.track('tour_ended', { completed });
  },
  onStepChange: (step, direction) => {
    console.log(`Moved ${direction} to step ${step.index + 1}`);
  },
});

// Per-step callbacks
const tour = useTour({
  steps: [
    {
      target: 'important',
      content: 'Key feature',
      onEnter: () => console.log('Entered important step'),
      onExit: () => console.log('Left important step'),
    },
  ],
});
```

## Conditional Steps

Skip steps based on runtime conditions:

```tsx
const [isPremiumUser] = useState(false);

const tour = useTour({
  steps: [
    { target: 'basic', content: 'Available to all users' },
    {
      target: 'premium',
      content: 'Premium feature!',
      condition: () => isPremiumUser, // Only shown if true
    },
    { target: 'footer', content: 'Thanks for touring!' },
  ],
});
```

Wrap your app with `TipMagicProvider` and configure tour options:

```tsx
<TipMagicProvider

    tourHighlightClass: 'tour-highlight', // CSS class for highlighted elements

  <App />
</TipMagicProvider>
```

```css
.tour-highlight {

    0 0 0 3px rgba(79, 70, 229, 0.4),
```

## Best Practices

### Keep Steps Concise

Each step should focus on one concept:

```tsx
// ✅ Good: Focused message
{
  content: 'Click here to create a new project.';
}

// ❌ Bad: Too much information
{
  content: 'Click here to create a project. You can also import, duplicate, or use templates...';
}
```

### Use Logical Flow

Order steps in the sequence users naturally discover features.

### Provide Exit Options

Always let users skip or exit the tour — use `showClose: true` in navigation.

### Use Focus for Important Steps

Enable focus mode on key steps to draw attention without overwhelming users.

- Tooltips are keyboard accessible
- Respects `prefers-reduced-motion` for animations
- Close button has proper ARIA labels
- Focus is managed appropriately during the tour
